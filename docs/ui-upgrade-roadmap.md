# 穗积的宇宙船 · UI / UX 升级路线图

日期：2026-09-24（调研开始于 2026-09-23）。状态：阶段 1 第二版三页样板已完成并通过本地验证，入口 `/design-preview`；等待视觉反馈后进入全站扩展。

## 目标与已确认决策

目标：让访客快速理解穗积的方向，通过文章、项目案例和交互细节认识个人能力，并获得适合持续阅读的体验。

已确认：**“穗积的宇宙船”强化为整站世界观，导航与页面都具有宇宙探索感。**

已确认：首要目标是技术影响力；个人定位是有产品与设计意识的全栈开发者；动效采用轻量反馈加首页一处探索互动；重点项目为 Cherry Studio App，参与移动端布局与核心功能实现，文案简短克制。

当前视觉约束：用户选择宇宙探索方向后，否定了第一版偏复古的观测仪表盘风格，并明确要求保留原紫色。**第二版采用原紫色的现代个人站视觉：清晰的大字层级、圆角、柔和层次、简洁导航和内容卡片。** 原主色 `oklch(58.52% 0.1694 287.57)` 保持不变；文字与实心按钮从原色派生对比度适宜的状态色。取消第一版的青色、密集编号与仪表盘细线，宇宙主题由首页紫色轨道雕塑和探索互动承载。

## 视觉方向选择

三个方向均保留整站宇宙世界观、中文内容优先和深浅主题；区别在于气质与装饰强度。

| 方向                                     | 视觉特征                                                                    | 优势与取舍                                                     |
| ---------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------- |
| A · 编辑式航行手记                       | 暖白、墨色与少量蓝色；细坐标、档案编号、星图插图；明确的文字层级            | 更温暖耐读，文字辨识度强；宇宙感依靠图形和编排建立             |
| B · 深空观测站（已选世界观，视觉已迭代） | 石墨黑 / 墨蓝、温白与单一信号色；轨道、定位点、精细网格；浅色版对应观测档案 | 与宇宙船世界观最直接契合；需要严格控制小字、低对比度和装饰密度 |
| C · 交互实验室                           | 更轻快的色彩、探测器与可操作演示；在作品和文章中加入解释性互动              | 更突出前端交互和创造力；需要持续维护高质量演示内容             |

以上三项为首次讨论时的备选。用户已选择 B 的宇宙世界观；后续反馈以本文件开头记录的第二版紫色现代个人站约束为准。正文仍遵循编辑式阅读结构。

动效建议：导航定位、主题切换、作品预览采用轻量反馈；首页可有一处标志性的探索互动。文章正文稳定呈现，系统开启减少动态效果时给出静态版本。大场景或可操控飞船属于需要单独选择的进阶方向。

动效程度选择：① 轻量反馈 + 首页一处探索互动（推荐）；② 以静态排版和图形为主；③ 首页更沉浸，加入可操作星图或飞船场景。选择③时，先独立验证首屏成本、触屏操作与静态降级，再纳入全站样板。

## 信息架构与世界观

导航优先显示清楚的功能名，宇宙名称作为副标题或页面主标题。主要入口建议优先突出文章、项目、关于，时间线、足迹、友链在二级探索入口中可直接到达；最终次序依首要受众调整。

| 功能       | 世界观表达（暂拟） | 路由与范围                                              |
| ---------- | ------------------ | ------------------------------------------------------- |
| 首页       | 舰桥 / 当前航向    | `/`：一句话定位、代表内容、在做的事、联系入口           |
| 文章       | 航行日志           | `/posts`：精选、主题、列表、搜索；保留原文章地址        |
| 文章详情   | 一篇完整航行记录   | `/posts/[slug]`：章节航线、正文、相关内容、评论         |
| 项目       | 建造档案           | `/projects`：补齐实际项目入口和案例；该页面当前尚未实现 |
| 时间线     | 航程               | `/timeline`：重要节点及对应作品、文章                   |
| 足迹       | 星图 / 到访坐标    | `/journey`：真实地点、照片与记录；地图配合可访问列表    |
| 关于       | 船员档案           | `/about`：身份、方法、经历、兴趣与联系                  |
| 友链       | 通讯频道           | `/friends`：友站介绍、链接与申请状态                    |
| 登录与后台 | 通行入口 / 舰务    | 现有登录与管理路由：统一表单、表格和状态反馈            |

导航配置还预留了 `/board` 留言板与 `/equipments` 装备库，目前没有对应页面。第一轮导航按实际可用内容组织，这两个功能记录为可选扩展；项目案例页因直接服务能力展示，列入本轮计划。

首页建议顺序：简短定位与两个核心入口 → 一篇精选文章 + 一个代表项目 → 最近文章 → 精选建造档案 → 当前关注与生活片段 → 订阅、社交和联系。受众以招聘或合作为主时，将代表项目前置。

文章建议主题：AI / Agent、Web 工程、项目实践；生活类随实际内容增长。分类数量与文章数量匹配。

## 个人能力的呈现方式

每个代表项目补齐一份可快速阅读的案例：

1. **问题与对象**：服务谁，解决什么问题。
2. **个人角色**：独立完成、负责的模块、参与阶段及协作范围。
3. **关键选择**：一到两个真正影响结果的技术或产品取舍。
4. **可见产物**：真实界面、交互演示、架构图、代码或贡献链接。
5. **结果与反思**：有来源的结果、当前限制和后续改进。

现有 Cherry Studio APP、清风卡社小程序、17b331 星图观测站和博客本身均可作为候选。首页选 2–3 个证据最完整的案例。站点配置中的 Star、用户量等数字需要确认来源和日期；项目整体指标与个人贡献分别表达。

阶段 0 同步建立素材清单：真实项目截图与演示、个人贡献链接、文章封面、个人头像、足迹摄影，并记录各项素材是否已经可用。按素材与贡献证据的完整程度选择第一个案例样板。

用户已确认个人定位是有产品与设计意识的全栈开发者。Cherry Studio App 的展示文案只说明移动端布局与功能开发；用户希望简单介绍，不添加未确认的功能职责、技术难点或量化业绩。

## 阅读与交互验收标准

- 以 1440px 桌面与 390px 手机作为样板，同时检查 360px、768px、1280px 及中间宽度。
- 首页在常见视口下直接呈现身份定位和内容入口；第一段滚动可看到代表内容。
- 中文正文以约 17–18px、1.8–1.9 行高、桌面约 36–40 个汉字宽度作为试排起点，依据实际字体、代码与长文调整。
- 标题长短、无封面文章、长标签、长代码、宽表格、Mermaid 图和空列表都有明确处理。
- 页面整体不出现意外横向溢出；代码、表格等宽内容在自身区域内滚动。
- 移动端有容易找到的目录入口；目录、锚点与固定导航不互相遮挡。
- 深浅主题分别检查正文、注释、边框、链接和焦点；普通正文不用弱化文字色承担全部阅读。
- 键盘可完成导航、搜索、主题切换、目录和表单操作；按钮与链接语义明确，弹层正确管理焦点。
- 减少动态效果、触屏、浏览器前进后退和滚动恢复单独验证；所有内容在动效降级后仍可访问。
- 以同环境的改版前后数据比较首屏加载、布局跳动和交互响应；生产构建数据与开发模式数据区分记录。本轮尚未建立性能基线。
- 回归检查原文章 URL、标题锚点、元数据、分享图、结构化数据、RSS 与站点地图；导航改版后检查断链和无法从站内到达的页面。

## 技术实施约束

- 基于现有 Next.js、React、HeroUI、Tailwind、MDX 完成升级；目前没有必要为 UI 更换框架。
- 遵循仓库 AGENTS.md，修改代码前读取所涉及的 `node_modules/next/dist/docs/` 本地文档；本轮已阅读字体与可访问性指南。
- 设计优先复用已有搜索、主题、目录、评论、缓存与地图能力；维护现有文章 URL、RSS、SEO 和数据行为。
- 交互组件按需加载；首屏品牌装饰、地图、代码演示和大字体文件的成本需要实际测量。
- 构建脚本包含内容同步、搜索上传与索引提交。实施时明确区分本地 UI 验证和会写入外部服务的发布流程。
